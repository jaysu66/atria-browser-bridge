# Atria Browser Bridge 使用指南

让 AI agent 操作你**真实的、已登录的 Chrome**。不是无头浏览器，不用重新登录。

---

## 零、让 agent 自己装（推荐）

把下面整段**原样复制给你的 agent**（Claude Code / Kimi CLI / Cursor / Codex 都可以），它会自己装好。中间只有加载扩展那一步需要你动手。

````text
帮我安装 Atria Browser Bridge —— 一个让你能操作我真实 Chrome 的本地桥。按以下步骤做，每步做完报告结果，失败就停下来告诉我原因，不要跳过。

1. 克隆仓库到我的主目录下：
   git clone https://github.com/jaysu66/atria-browser-bridge.git ~/atria-browser-bridge

2. 检查 Node 版本 >= 18：node --version

3. 跑自检，确认服务端契约完好：
   cd ~/atria-browser-bridge && node scripts/smoke-mcp.js
   期望输出包含 "26 tools (26 required present)" 和 "protocol=2"。
   数字对不上就停下来告诉我。

4. 把 skill 装进你自己的 skill 目录（按你所在的 harness 选一个，不确定就问我）：
   Claude Code → cp -r ~/atria-browser-bridge/skills/atria-browser-bridge ~/.claude/skills/
   Kimi CLI    → cp -r ~/atria-browser-bridge/skills/atria-browser-bridge ~/.kimi-code/skills/
   如果你的 harness 不支持 skill 而支持 MCP，改用：
   claude mcp add browser -- node ~/atria-browser-bridge/mcp-server.js

5. 设置环境变量 ATRIA_BROWSER_BRIDGE_HOME=~/atria-browser-bridge
   （只有当你没把仓库放在 ~/Desktop/atria-browser-bridge-oss 时才需要，
     skill 的辅助脚本靠它找到 mcp-server.js）

6. 现在停下来，让我做唯一需要人工的一步。原样告诉我：
   「请打开 chrome://extensions，开启右上角的开发者模式，点『加载已解压的扩展程序』，
     选择 ~/atria-browser-bridge/extension 目录，然后点一次扩展图标打开 popup。
     最后一步不能省——service worker 靠打开 popup 才开始轮询。装好告诉我。」

7. 我说装好后，验证连接：
   node ~/atria-browser-bridge/skills/atria-browser-bridge/scripts/bridge.js --health
   期望 bridgeState.extensionVersion 非空、protocolVersion 为 2。
   如果 extensionVersion 是 null，说明扩展没连上，让我重新打开一次 popup。

8. 最后跑一次真实验证：打开 https://example.com，读取页面，把标题告诉我。

装完后简单说明我能让你做什么，以及一句话安全提示：这个桥不做任何脱敏，
页面上的内容（包括表单里填的值）会原样进入你的上下文。
````

装完之后你就可以直接说「打开某某网站」「把这个页面抓下来」「帮我填这个表单」。

## 一、手动安装（一次性）

### 1. 启动本地桥

```bash
node mcp-server.js --standalone
```

用 skill 的话这步可以跳过——脚本会在连不上时自己拉起来。

### 2. 装 Chrome 扩展

1. 打开 `chrome://extensions`
2. 右上角开启**开发者模式**
3. 点**加载已解压的扩展程序**
4. 选本仓库的 `extension/` 目录
5. **点一次扩展图标打开 popup** ——这步不能省，service worker 靠它开始轮询

验证：

```bash
node scripts/smoke-mcp.js
```

看到 `26 tools ... protocol=2` 就对了。

### 3. 接上 agent

**方式 A：当 skill 用**（不需要配 MCP）

```bash
cp -r skills/atria-browser-bridge ~/.claude/skills/       # Claude Code
cp -r skills/atria-browser-bridge ~/.kimi-code/skills/    # Kimi CLI
```

**方式 B：当 MCP server 用**

```bash
claude mcp add browser -- node /绝对路径/atria-browser-bridge/mcp-server.js
```

两种可以并存，driving 的是同一个桥。

## 二、调用方式

### skill 模式

```bash
node "<skill目录>/scripts/bridge.js" <工具名> @参数文件.json
```

**参数必须走文件，不要内联 JSON。** Windows PowerShell 5.1 会把内联 JSON 的内层双引号吃掉，必然解析失败。

脚本的三个约定：

- **stdout 只有工具返回值**，可以直接 `json.load`
- **`[raw]` 等元信息走 stderr**
- **截图和 PDF 落盘**，返回文件路径而不是 base64（模型看不了 base64）

### 直连 HTTP

跳过 agent 自己写驱动脚本时最快：

```bash
curl -X POST http://127.0.0.1:47652/tools/call \
  -H 'Content-Type: application/json' \
  -d '{"name":"tabs_context","arguments":{}}'
```

多步操作塞进一个进程，能绕开"每个动作一次 agent 往返"的开销。

## 三、核心用法

### 点击和输入：一律用 `computer`

`computer` 走真实 CDP 输入，事件带 `isTrusted=true`。`javascript_tool` 是页面内合成事件，canvas 图块、拖拽区、富文本编辑器都不认。

**凡是要产生实际效果的交互，不要用 JS 点。**

传 `ref` 和传坐标同样是真实输入——`ref` 会先解析成实时坐标、滚动到视野、检查有没有被遮挡，然后发同样的事件。优先用 `ref`：

- 抗 class 名 hash 变化
- 每次调用重新解析坐标，页面重排不会点到别的元素上
- 被浮层挡住时直接报错，而不是误点

**坐标绝对不要跨步复用。**

### 填表单

```json
{"ref":"ref_32","value":"要填的内容"}
```

`form_input` 写完会**回读校验**。返回 `write_not_applied` 说明编辑器拒绝了写入（ProseMirror / Lexical 常见）——改用：

```json
{"action":"type","ref":"ref_32","text":"要填的内容"}
```

这条会点进输入框再真实键入，同样回读校验。两条路径都不会在没填进去的时候告诉你填好了。

### 过验证码页

```
navigate → 看返回里的 pageState.challenge
  ↓ 不为 null
tabs_activate      # 把页面顶到用户面前
告诉用户去点
wait_for {"challengeGone": true, "timeoutMs": 600000}
  ↓
继续
```

不要试图自动破解验证码。检测 + 等人是唯一正确形态。

### 爬列表页

```json
{"scopeSelector": ".product-grid", "maxItems": 100}
```

返回里直接有：

- `items[]` —— 自动识别的卡片数组（同一父容器下 ≥3 个同构子节点）
- `pagination.next` —— 下一页链接

无限滚动加 `incremental: true`，只返回上次之后的新增项。

**提速两件事：**

```json
{"resourceTypes": ["image", "font", "media"]}
```
`set_request_blocking` —— 这些通常占页面流量 60-80%。

```json
{"filter": "api"}
```
`network_start` —— 列表页多半由 XHR JSON 驱动。抓到响应体直接读 JSON，比解析 HTML 快一个数量级。

### 并行

```json
{"batches": [
  {"tabId": 101, "actions": [{"name":"navigate","input":{"url":"..."}}, {"name":"extract_page","input":{}}]},
  {"tabId": 102, "actions": [{"name":"navigate","input":{"url":"..."}}, {"name":"extract_page","input":{}}]}
]}
```

每个 batch 独立，一个挂掉不影响其他。配合 `ATRIA_BROWSER_MIN_INTERVAL_MS` 做全局域名限速——并行时各跑各的限速等于没限速，所以限速收敛在桥这一层。

---

### 虚拟列表 / 无限滚动

```json
{"action": "scroll_until", "selector": "[data-id='xyz']", "maxSteps": 20}
```

`scroll` 和 `scroll_until` 走 CDP 真实滚轮事件。**不要用 `javascript_tool` 改 `scrollTop` / 调 `scrollBy`** —— 那样视口是动了，但不触发 `wheel`，虚拟列表永远不加载下一批。

### 树里找不到的元素

图片网格、canvas 图块这类元素在无障碍树里没有 ref。别手写选择器再算坐标：

```json
{"action": "click_where",
 "predicateJs": "el => el.src.includes('b93eeb3c')",
 "selector": "img",
 "verifyJs": "() => document.querySelector('.selected') !== null"}
```

一次调用完成「定位 → 滚进视野 → 检查遮挡 → 真实点击 → 校验」。坐标在调用内部当场解析，不存在过期问题。

### 写带正则的 JS

JSON 字符串里的 `\s` `\d` 必须写成 `\\s` `\\d`，很容易踩。直接绕开：

```bash
node "<skill目录>/scripts/bridge.js" --js myscript.js [tabId]
```

脚本按文件读，不经过 JSON 转义。

## 四、稳定契约

以下接口有外部调用方依赖，视为稳定，变更会在 CHANGELOG 里显式说明：

- `POST http://127.0.0.1:47652/tools/call`，body `{name, arguments}`
- 响应结构 `result.content[]`，其中 `{type:'text', text}` 承载返回值
- **`javascript_tool` 的返回是 `{"result": <真实返回值>}` 的二层包装**
- `computer` 的 `left_click`（`coordinate` 与 `ref` 两种形式）、`type`、`key`、`scroll`

## 五、配置

| 环境变量 | 默认值 | 作用 |
|---|---|---|
| `ATRIA_BROWSER_PORT` | `47652` | 桥端口，要和扩展 popup 里的一致 |
| `ATRIA_BROWSER_HOST` | `127.0.0.1` | 监听地址 |
| `ATRIA_BROWSER_MIN_INTERVAL_MS` | `0` | 同域名两次导航的最小间隔 |
| `ATRIA_BROWSER_REQUEST_TIMEOUT_MS` | `60000` | 单请求超时（`wait_for` 和批量调用自动放宽） |
| `ATRIA_BROWSER_BRIDGE_HOME` | `~/Desktop/atria-browser-bridge-oss` | skill 脚本找 `mcp-server.js` 的位置 |

## 六、安全边界

**这个桥不做任何脱敏。** 页面内容原样返回，包括表单里的值——密码、验证码、卡号都不例外。页面上有什么，就会进 agent 上下文，进而到你的模型服务商和会话日志里。

**只在你愿意把内容贴进聊天窗口的页面上用它。**

`export_session` 会交出某个域名的 cookie 明文。默认关闭，必须在扩展 popup 里手动开——开关放在浏览器里而不是 agent 配置里，就是为了让 agent 无法自己授权。

明确不做的事：

- 自动识别验证码 / 接打码平台
- 绕过 `isTrusted` 检测的指纹伪装
- 无头模式（与"用户真实浏览器"这个核心价值矛盾）

## 七、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 连接被拒 | 桥没起 | `node mcp-server.js --standalone` |
| `ok:true` 但 `lastSeenAt:null` | 扩展没连上 | 重新打开扩展 popup |
| `versionWarning` 有值 | 扩展是旧版 | 到 `chrome://extensions` 点刷新 |
| `TAB_GONE` | 标签被关了 | `navigate` 加 `recreateIfGone:true` |
| `write_not_applied` | 编辑器拒绝合成写入 | 改用 `computer` 的 `type` |
| 点击报"被遮挡" | 有浮层挡着 | 先关掉浮层（用 × 不用 Escape，Escape 常会连带清空已选内容） |

**改了扩展代码之后必须去 `chrome://extensions` 点刷新**，MV3 的 service worker 和 content script 都不热加载。注意这会打断正在跑的任务。

**扩展一次只处理一条桥指令。** `wait_for` 挂着的时候，其他调用会排队等它返回 —— 所以不要指望"一边等一边干别的"。这对它的设计用途没影响（用户是在浏览器里点掉验证码，不是通过桥），但写驱动脚本时要知道。

## 八、验收

```bash
npm run smoke     # 服务端契约,不需要浏览器
npm run accept    # 完整浏览器验收,需要扩展已连接
```

`npm run accept` 会自己起 fixture 服务器、开标签、跑完 14 项检查再清理干净。每一项都对应一个真实报告过的故障，不是演示。
